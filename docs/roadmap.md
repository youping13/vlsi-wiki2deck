# Roadmap：wiki2deck 之後可以長成什麼

> 2026-11-21 語音討論時記下，作業交完再做。順序 = 實用性。

## 1. 輸出成 Google Slides
- 渲染器多一個 target：`render --to gslides <簡報連結>`，把 deck.json 的每頁寫成 Google Slides 的版型（標題、bullet、圖、講稿放 speaker notes）
- 限制：Claude 只能編輯已經存在的簡報 → 先開一份空白 Google Slides，把連結給 Claude
- LaTeX：Google Slides 不支援，公式先轉成圖片（KaTeX → PNG）再插入

## 2. 論文 ＋ 自己的筆記合併（筆記為主）
- 配對：同一篇的論文和筆記用同一個檔名開頭（`liu2010.pdf` ＋ `liu2010-note.md`），或放在同一個資料夾
- 合併規則：**筆記是骨架**（保留我的思考順序與觀點），論文只負責補證據、數字和圖；兩邊說法衝突時標在「衝突」段落
- 筆記格式：Markdown 直接用；手寫 PDF → 先轉成 Markdown＋LaTeX，**人工核對一次**（下標、正負號最容易認錯）再進流程
- 新增關卡：note-faithfulness，檢查合併後的段落順序和筆記一致

## 3. 分類樹＋關係圖（像技能樹）
- 第一層：父類別／子類別樹，例如 類比電路 → ADC → SAR → 切換方式；每篇論文和筆記掛在一個節點下
- 第二層：關係線，分成「延伸自」、「對比」、「前置知識」→ 可以看出閱讀順序
- 分類由誰做：Claude 先提案，我確認（先討論、後生成）
- 輸出：可點開的互動圖；之後可能接到 my world 的技能樹（還在考慮）

## 4. 個人風格的快速簡報（宣傳、介紹用）
- 我給文字大綱＋幾張圖 → 自動生成簡報（HTML 或 PPT）
- 分工：AI 負責判斷（切頁、選版型、配圖、縮短過長的字）→ **我確認頁序** → 腳本負責固定工作（套風格、裁圖、輸出、檢查有沒有爆版或漏圖）
- 風格：從我給的 2–3 份代表作品抽出顏色、字型、版面，做成主題檔；先套出幾種版型讓我挑，確認後才鎖定
- 跟這次作業的關係：同一個模板和渲染器，只是跳過 wiki 和證據關卡
